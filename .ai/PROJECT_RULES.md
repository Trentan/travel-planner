# Project Rules

## Mission
Build a reliable, polished travel planner app ready for production release. Quality beats features.

---

## Principles
1. Never break existing functionality.
2. User experience comes first.
3. Every change requires verification.
4. Avoid unnecessary rewrites.
5. Prefer simple maintainable solutions.

---

## Before Changing Code
Understand:
- Current architecture
- Existing patterns
- Existing tests
- User impact

---

## Every Change Must Consider
- Functionality
- UX
- Accessibility
- Performance
- Regression risk
- Testing

---

## Never
- Add unnecessary features
- Remove working functionality
- Make large architectural changes without approval
- Skip testing
